What would the leaderboard look like on unseen tasks?

A leaderboard score is an average over a limited set of tasks. RULER estimates how each position's score would change on an unseen set of tasks from the same benchmark, and how much the order would change.

Why the top score is inflated

Each model's score combines its ability with luck: the tasks that happened to be in the benchmark suited some models better than others. Sorting by score puts the models whose luck was good near the top. So the #1 score tends to overstate what the #1 model would score on unseen tasks. This is the winner's curse, and it affects every position: scores near the top tend to be inflated, and scores near the bottom deflated.

The simulation below makes the effect visible. Every model has the same true accuracy, so the winner of each draw is simply the luckiest one.

Step 1 · Rebuild the leaderboard from resampled tasks

RULER draws tasks at random, with replacement, from the benchmark's {% filter tex %}N{% endfilter %} tasks. Each drawn task brings every model's result on it, so models that do well on the same tasks stay linked. RULER recomputes every model's average, sorts the models, and repeats this {{ "{:,}".format(analysis.n_bootstraps) }} times.

Note. Each rebuilt leaderboard uses {% filter tex %}m = \lfloor N^{ {{ analysis.gamma }} } \rfloor{% endfilter %} tasks, fewer than {% filter tex %}N{% endfilter %} (the exponent {{ analysis.gamma }} is a predeclared heuristic). With fewer tasks, close models swap places about as often as they would on unseen tasks. Under exact population tiers, this gives a valid bias correction and the correct limiting rank probabilities.

Step 2 · Adjust each position's score

At each position, RULER compares the rebuilt leaderboard's score with the same model's score on the full benchmark. The average gap, scaled by {% filter tex %}\sqrt{m/N}{% endfilter %} to the full benchmark's noise level, is that position's estimated inflation. The adjusted score is the observed score minus this estimate. Systems tied on the leaderboard share the average adjustment of the positions they occupy.

Step 3 · Record where each model lands

The rank probability matrix records how often each model lands at each rank across the rebuilt leaderboards. When models tie in a rebuilt leaderboard, they split the credit equally among the ranks they occupy.

Step 4 · Rank ranges and tiers

A model's rank range is the middle 80% of its ranks across the rebuilt leaderboards. Tiers come from walking down the observed order: a tier grows while all of its members' rank ranges share at least one rank, and a new tier starts when they no longer do. A tier marks the limit of what the benchmark's tasks can resolve: its members may still differ in capability by amounts the tasks cannot detect. Ranges and tiers at 90%, 95%, and 99% are in each leaderboard's report.

Does the adjustment work?

The paper checks it two ways. In sample splitting, half of each benchmark's tasks rank the models and the other half scores them. Across settings, the adjustment reduces the average magnitude of the mean rank-1 split error from 2.41 to 0.76 pp. In a simulation calibrated to SWE-bench Verified, where true abilities are known, it reduces the mean winner bias from 1.41 to 0.21 pp. The adjustment reduces systematic inflation but can overshoot at some positions, and a single leaderboard's scores stay noisy.

What it measures

RULER measures the uncertainty that comes from which tasks are in the benchmark, holding the released model responses and judge scores fixed. Two conditions shape the results:

  • Tasks are treated as independent draws. The paper's cluster analyses check this for SWE-bench repositories and Tau2 telecom subcategories.
  • The guarantees assume clear gaps or exact ties. When true gaps are comparable to sampling noise, the paper's local analysis shows that the leading bias cannot be consistently estimated for every population.

Rerunning models or judges, contamination, adaptive submissions, and whether a benchmark measures the intended capability are separate questions.

Settings on this site

Every report uses the same settings: {% filter tex %}m = \lfloor N^{ {{ analysis.gamma }} } \rfloor{% endfilter %}, {{ "{:,}".format(analysis.n_bootstraps) }} rebuilt leaderboards, seed {{ analysis.seed }}, and rank ranges at 80%, 90%, 95%, and 99%. For the snapshots analyzed in the paper, every build checks the numbers against the paper's committed results.

Run it on your own leaderboard

from llm_wc.wc.ruler import ruler

# obs: (N tasks, J models) array of per-task scores in [0, 1]
r = ruler(obs)              # m = floor(N**0.9), 5,000 resamples, seed 42
r.adjustment                # score adjustment at each position, in observed order
r.rpm                       # rank probability matrix (models x ranks)
r.intervals[0.2]            # (rank_low, rank_high, tier) at 80%
r.tiers[0.2]                # tiers and the ranks their members share

RULER stands for Rank Uncertainty and Leaderboard Evaluation Report.
