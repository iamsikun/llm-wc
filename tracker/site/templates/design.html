How many tasks, and how large a lead?

A benchmark's tasks set how finely it can rank models. One rule answers two questions: how many tasks a benchmark needs, and how far ahead a new #1 must be to claim the top spot.

Under the exact-tier approximation, the top score's expected inflation with {% filter tex %}N{% endfilter %} tasks is about

{% filter tex(true) %}b_N(1) \approx \delta/\sqrt{N}.{% endfilter %}

Here {% filter tex %}\delta{% endfilter %} is the winning gap within the top tier. Both calculators estimate it from a leaderboard's current inflation at #1, {% filter tex %}\hat{b}_N(1){% endfilter %}, as {% filter tex %}\hat\delta = \sqrt{N}\,\hat{b}_N(1){% endfilter %}.

How many tasks does a leaderboard need?

Halving the inflation takes about four times as many tasks. To bring the inflation at #1 down to a target {% filter tex %}\varepsilon{% endfilter %}, plan

{% filter tex(true) %}N \gtrsim (\delta/\varepsilon)^2.{% endfilter %}

How large a lead does a new #1 need?

A lead smaller than the top score's expected inflation is within the luck of the draw. For a confident claim with {% filter tex %}N{% endfilter %} tasks, a new #1 should beat the previous best score by more than

{% filter tex(true) %}\delta/\sqrt{N}.{% endfilter %}

These are planning figures. They hold the models, the task distribution, and the correlations between models fixed. Close gaps or a changing model pool change the extrapolation. A lead larger than the inflation is not the end of the check: the new #1's RULER report shows whether it is separated from its closest competitors.

Add a leaderboard

The tracker can analyze a leaderboard that publishes every model's score on every task. It needs:

  1. Per-task scores: each model has a score on each task.
  2. Stable task IDs: each (task, model) pair appears once, or repeats follow a stated rule, such as averaging the trials or keeping one submission.
  3. A shared task pool that every included model was scored on. RULER uses the largest such block, as the paper does for LiveBench.
  4. At least {{ criteria.min_tasks }} tasks and {{ criteria.min_models }} models in that pool.
  5. Scores on a fixed scale: numbers in [0, 1], or in [0, 100] or [1, 10], which are rescaled.

Any table with one row per (task, model) pair works, in CSV, JSON Lines, or Parquet:

task_id,model_id,score
django__django-11099,model-a,1
django__django-11099,model-b,0
astropy__astropy-12907,model-a,0.5

Check it with the feasibility probe, then propose it as a GitHub issue:

uv run python -m llm_wc.tracker probe scores.csv
uv run python -m llm_wc.tracker probe hf:your-org/your-leaderboard-results
