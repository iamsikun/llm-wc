For benchmark designers

How many tasks does a leaderboard need?

A benchmark's tasks set how finely it can rank models. Plan enough tasks for the precision you need, and publish the uncertainty that remains.

Task-pool sizing

Tasks needed for a target inflation

Under the exact-tier approximation, the top score's expected inflation is about {% filter tex %}\delta/\sqrt{N}{% endfilter %}, so halving it takes about four times as many tasks. To reach a target inflation {% filter tex %}\varepsilon{% endfilter %}, plan

{% filter tex(true) %}N \gtrsim (\delta/\varepsilon)^2.{% endfilter %}

Here {% filter tex %}\delta{% endfilter %} is the winning gap within the top tier. The calculator estimates it from the leaderboard's current inflation at #1, {% filter tex %}\hat{b}_N(1){% endfilter %}, as {% filter tex %}\hat\delta = \sqrt{N}\,\hat{b}_N(1){% endfilter %}.

Reporting checklist

What to publish with a ranking

  • ✓
    Per-task scores for every modelThe task-by-model matrix makes uncertainty analysis possible, including this one. Give tasks stable IDs.
  • ✓
    The same task pool for every entryIf some models ran on a subset, state which.
  • ✓
    Adjusted scores next to raw scoresThe raw leader's score tends to overstate its expected score on fresh tasks. Show the adjustment at each position.
  • ✓
    Rank ranges and tiersSay which models the tasks cannot order, at a stated level such as 80%.
  • ✓
    The rank probability matrixShow how ranking uncertainty spreads beyond the leaders.
  • ✓
    Score definition and target populationWhat a task is, how it is scored, and what population the tasks stand for, including judge and version details.
  • ✓
    Dependence structureClusters such as repositories or domains, so others can resample at the right level.
  • ✓
    Versioned snapshotsDate every release of the leaderboard so results can be reproduced as entries are added.

Share your leaderboard's data

Any table with one row per (task, model) pair and a score in [0, 1] works, in CSV, JSON Lines, or Parquet:

task_id,model_id,score
django__django-11099,model-a,1
django__django-11099,model-b,0
astropy__astropy-12907,model-a,0.5

Check it with the feasibility probe, then propose it on the coverage page:

uv run python -m llm_wc.tracker probe scores.csv
uv run python -m llm_wc.tracker probe hf:your-org/your-leaderboard-results
